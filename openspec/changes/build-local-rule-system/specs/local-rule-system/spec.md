# Local rule system
## ADDED Requirements
### Requirement: 有来源的统一规则优先级
系统MUST按设计顺序独立决策分类/账户，返回来源/分数及解释，所有结果受清单约束。
#### Scenario: 学习与覆盖冲突
- WHEN 用户手动记住的分类与外置/内置规则冲突
- THEN 使用手改来源，删除后恢复其他有效规则，跨交易类型不复用。
### Requirement: 外置规则和统计
系统MUST支持本地JSON导入/导出/恢复默认，限量校验并原子生效；近7天包名结果聚合持久化有界；样本保存维护索引。
#### Scenario: 导入坏文件
- WHEN 文件过大、坏JSON、字段不合法或危险正则
- THEN 明确报错且原配置仍可用，正常采集不崩溃。
#### Scenario: JSON页面匹配
- WHEN 有效覆盖规则匹配账单页
- THEN 识别来源为JSON；列表/失败等反向排除仍有效。
### Requirement: 餐饮账单时间兜底
系统MUST用账单本地时间匹配可配置餐段，支持跨零点和间隔，不覆盖明确非三餐子类或已学习餐别。
#### Scenario: 边界与缺少分类
- WHEN 账单在10:30或21:00或用户清单缺少餐段名
- THEN 匹配半开区间且仅返回清单存在的名字；未授权不得改用户清单。
### Requirement: 成功确认后的本地学习
手改MUST立即学习、人工连续接受同推荐3次后弱学习；其他保存源不计数；保守商户归一，账户按支付上下文。
#### Scenario: 相同店铺不同餐时与付款方式
- WHEN 连续三次接受午餐后晚上以另一账户付款
- THEN 不把午餐固化给所有时间，不串用另一付款方式的账户。
#### Scenario: 取消、重复或失败
- WHEN 保存被取消、失败、去重跳过或自动确认
- THEN 学习数据不改变。
### Requirement: 可维护可迁移
设置MUST允许编辑餐段、删除/清空学习、查看命中统计；JSON备份MUST往返配置并兼容旧文件，删除的分类账户不再被建议。
#### Scenario: 恢复旧备份
- WHEN 旧备份没有规则字段
- THEN 保持已有新规则与餐段配置，不清空或污染。
