# 实施设计
1. 统一规则候选：显式手改学习>用户JSON覆盖>随包JSON>弱频次学习>内置规则>餐段兜底；同来源按实际匹配具体程度（匹配词长度）及稳定序号。分类和账户独立选优，只返回当前清单内有效项。分类规则区分INCOME/EXPENSE/REFUND/TRANSFER，跨类型不得污染。
2. B2 JSON支持页面识别规则与分类/账户关键词规则。随包默认+SAF导入覆盖文件（原子替换、校验失败保持现有配置），导出/重置入口，标示版本和来源；允许contains/受限正则，限制文件大小/数量/表达式长度，拦截明显危险正则，不能以任意巨大正则阻塞采集。billkit无Context，宿主读取注入；测试不得使用android.jar org.json空桩。反向页面排除先于JSON和内置，JSON无效不导致全链路失效。
3. 餐段默认05:00–10:30早餐、10:30–14:30午餐、16:30–21:00晚餐、21:00–05:00夜宵，空档回三餐/仅一级。可编辑半开区间、跨零点，拒绝重叠与非法HH:mm。只已定餐饮且非咖啡茶饮/零食等明确子类时兜底；显式餐名先于时间；用draft.timeMillis及设备本地时区，不用当前时间替代。新装默认新增早餐/午餐/晚餐/夜宵；已自定义清单不静默追加，UI明确提供补齐餐段分类按钮。
4. 学习：用户确认成功落库后才更新；手动改分类/二级/账户仅记录改动字段，不覆盖未改字段。取消、失败、重复、自动确认、备份导入不累计；历史编辑若纳入只允许用户明确修改且成功，不算频次。商户保守归一（空白及明确括号分店后缀），不能过度合并不同商户；账户学习结合支付方式上下文，防同商户不同付款方式串账。3次是连续且同一有效结果，变更重置；时间产生的餐别不被频次固化，手改餐别可覆盖时间。无商户不学习。可逐条删除/全部清除，删除不在下一次立即复活旧候选；对已删除分类/账户自动忽略。
5. 学习及餐段配置使用ledger_config扩展，备份可往返并兼容旧文件（旧备份缺新字段保持现有配置），不改Room表；新字段纯MiniJson序列化可单测。原始和最终草稿对比必须贯通Activity、overlay、pending确认入口及BillWriter成功结果；避免只在某一UI回调学习。
6. B4近7天包名+结果计数有界持久化，不存全文/敏感原文；不依赖StateFlow可能丢事件的collect采样，直接接DebugBus发布钩子宿主注入；诊断页显示、清空，学习来源标注接DebugBus。B1样本索引文件与保存同路径，文本索引不破坏夹具导出。
7. UI在设置提供规则管理（JSON导入导出/清除、餐段编辑、已学习规则删除、覆盖统计），清楚说明优先级、仅本机和备份范围；不暴露实现术语给普通用户。先不生成正式release/dist，沿用用户上一轮预览要求；先单测+debug并安装已有可见模拟器验证，可后续用户决定出包。版本不变则明确预览源码与dist不同。
8. 并行边界：核心代理data引擎/策略/存储/备份及tests；JSON与统计代理billkit规则/DebugBus与app桥接独立文件、B1；UI整合代理App/确认保存链/UI及最终构建（依赖前两者）。各代理直接沟通接口，禁止覆盖其他人文件。
