## 一、新增需求

| ID | 需求 | 完成时应看到的结果 |
|---|---|---|
| N1.1 | 手动记账金额重新输入 | 新建时0.00作为展示/占位，首次点击直接输入新金额，无须删0.00；失焦空值不存成0；再次点击不丢已输入值。识别金额和历史编辑建议全选便于替换，不自动清空真实金额。 |

| N1.5 | 主确认卡隐藏单号尾号 | 确认卡不再占一行；后台数据及去重仍保留，详情按需展示。 |
| N1.6 | 底部只留两动作 | 自动确认/新建场景底部仅“导入 iCost”“记一笔”，顶部灰色“忽略”作为唯一显式忽略按钮；不再有底部忽略。编辑已有账单主动作显示“保存修改”，不重复入库。 |
| N1.7 | 控制弹框高度 | 普通字号、键盘关闭时目标可用屏高约50%–65%；长备注或大字号可扩展/内部滚动，键盘弹出仍能到达金额和主操作。不为半屏裁切文本或缩小点击区域。 |
| N2.1 | 周、月统计图 | 周/月切换；柱状图看每日趋势，饼图/环图看分类占比，保留金额和百分比文字；周期可前后切换，无数据和单分类正常。退款独立展示，结余=收入−原支出+退款，转账不混入收支。 |
| N3.1 | 明细顶部“识别历史” | 顶部入口显示待处理数量；进入可看已成功识别的记录，暂时没空时稍后继续；不能只依靠当前20条待确认队列。 |
| N3.2 | 历史处理与持久化 | 识别成功先持久化，再尝试弹卡。记录识别时间、账单时间、来源、金额、处理状态；支持待处理/已记账/已忽略筛选，重新打开确认，入库后关联账单。重启仍在，重复采集不无限增殖或重复入账。 |
| N4.1 | 点击账单打开操作页 | 先展示账单摘要及“修改、删除、查看详情”，不再直接进入编辑；修改保持原账单ID，删除沿用独立5秒撤销，详情显示时间/分类/账户/备注/来源及已有商户和单号等，不伪造缺失字段。首页最近账单与明细行为一致。 |

### 交互与数据约束

- 长按滑选必须区分横向滚动、长按、滑选、下拉关闭；浮层贴近按下位置且不超出屏幕安全区，切换分类后旧二级选中态不能残留。
- 备注气泡与B6商品抽取可衔接，但第一版不以B6完成为前提；建议默认提供少量本地建议，采用追加/替换的明确动作，不接云服务。
- “忽略”建议将识别记录标为已忽略，仍可在历史回看；手动新建关闭只取消草稿。下滑/点外部关闭的状态转换需统一，建议保留待处理而非直接删除。
- iCost按钮当前是先本地保存再发起分享，不能等同第三方导入成功。N3须分别记录本地已记账与外部“已发起导入”，分享失败也不能将已有本地账重新当待记而重复入账；外部完成状态只能由用户确认。保留退款阻止提示。
- 识别历史保存的是成功生成的草稿，失败/节流诊断属于F14，不把聊天文本或整屏原文默认永久存入历史。不能恢复此前未保留的数据。建议从现有PendingStore迁移待处理项，去重合并且迁移可重入。
- 待处理记录不因数量上限静默淘汰；保留期限、清理及备份策略在N3设计时明确，清理仅由用户操作。历史入库与状态关联需处理崩溃、双击、删除撤销及恢复后关联失效。
- 建议默认周一到周日、自然月、设备本地时区。图表遵循减少动效设置，提供文字摘要，不能只用颜色表达。周/月切换与周期横滑复用同一时间区间逻辑。

## 四、统一验收与证据

1. 确认卡覆盖新建、自动识别、历史补记、编辑四入口；0.00点击直接输入、非零不丢、非法值禁存、19.99精度、取消不学、保存仅一次。
2. 手势录屏涵盖长按展开、横滑逐项高亮、松手提交、移出取消、快速反向、无二级、横向滚动冲突；减少动效不影响最终结果。
3. 单行分类/账户在大量项目、长名称、深浅主题、大字号下仍可使用；排序重启和JSON备份恢复后相同。
4. 常规字号无键盘检查半屏到约三分之二目标；小屏、大字号和键盘出现时主要动作可达，不强行半屏。
5. 识别成功但来不及处理，重启后历史仍可补记；反复打开成功页、重复点击、入库中崩溃不生成重复账单；已忽略可回看，清理不误删账本。
6. 周跨年、月跨年、闰日、周/月边界、空数据、退款和转账分别验证；图表汇总与同周期明细一致，查询无隐藏条数截断。
7. 账单操作页修改保持身份和创建时间，删除5秒撤销独立有效；详情缺字段显示合理占位，返回不丢列表位置。
8. 变更对应单测全绿再构建；交run manifest、测试结果、模拟器截图/录屏，涉及支付投递/功耗必须补真机证据。用户明确接受前始终“待验收”。
