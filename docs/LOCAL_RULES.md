# 本地规则与学习

日常规则入口为 **设置 → 识别规则**，自动记账页也有同名入口。应用范围、学习记忆、通知模板、餐段与统计仍在自动记账的更多设置中。SPEC 分类/账户填充与本地配置共用同一保存链路。

当前源码官方包1.3.0/15条、maimi-rules-5；历史首包1.0.0/14条仅按当时解释。通知监听和页面识别独立授权，规则不能绕过结果页/详情准入或通知门禁。

## 推荐优先级与学习

分类和账户分别评分选择，各自显示来源；仅使用当前分类/账户清单中存在的名称。来源基础权重从高到低为：手动学习 600、导入 JSON 500、随包 JSON 400、确认学习 300、基础规则 200、餐段 100；匹配细节参与评分。手动确认页仍可覆盖推荐。

- 人工成功保存后，明确修改分类/子类或账户会立即记住；沿用同一推荐连续成功确认 3 次后才形成确认学习。
- 分类按账单类型与规范化商户识别；账户还关联支付方式，避免同商户不同支付方式串用账户。分类与账户独立累计。
- 取消、忽略、重复、保存失败及自动确认不累计学习。历史账单编辑的明确修改可学习，但不会累计「接受 3 次」次数；普通手动新增不用于这条确认学习链路。
- 关闭学习会同时暂停新增学习与已有学习推荐。可以单条删除或清空；删除后新确认重新累计，已有手动学习不被弱确认学习覆盖。
- 学习记录与餐段保存在本机，随账本备份；删除分类或账户后，对应无效名称不再推荐。

餐段使用账单发生时间和本机时区，起点包含、终点不包含，支持跨午夜、禁止重叠。默认早餐 05:00–10:30、午餐 10:30–14:30、晚餐 16:30–21:00、夜宵 21:00–05:00，空档按现有清单回退三餐或餐饮一级；明确咖啡、零食等子类保持原样。页面可补齐缺少的早餐/午餐/晚餐/夜宵子类，不覆盖已有配置。

## JSON 文件（version 1）

先从页面导出当前 JSON 作为模板，编辑后导入。导入失败保留当前覆盖文件与正在使用的规则；整份校验通过后才原子替换。恢复随应用规则仅移除导入覆盖，保留学习与餐段。

覆盖文件是增补：同一字段冲突时按优先级评分，未命中的随包规则仍保留；导入空数组不会禁用随包规则。列表、支付输入等反向排除优先，JSON 页面规则不能绕过成功状态和金额校验。

根对象为 `version:1`、`rules`（页面）、`categories`（分类）、`accounts`（账户）；完整示例见 [`rules.json`](../app/src/main/assets/rules.json)。

- 页面字段：`packages` 包名数组、`kind` 现有 PageKind、`require` 条件数组、可选 `anyOf` 条件组数组、可选 `exclude` 条件数组、`strategy` 名称。所有 require 须命中，每个 anyOf 组至少命中一个，任一 exclude 命中即拒绝。
- 分类字段：`type`（EXPENSE/INCOME/REFUND/TRANSFER）、`keywords` 文字数组、`category` 和可选 `subCategory`。账户字段以 `account` 代替分类，默认 `matchMethod:true` 匹配支付方式；分类默认匹配商户及备注，也可显式设置 `matchMethod`。
- 支持 `match:"contains"` 或省略。关键词为普通文字；页面表达式只支持 `|` 文字备选，例如 `支付成功|交易成功`，不执行任意正则。`regex` 与未知字段会被拒绝。
- 文件最多 64 KiB、总计 200 条规则、展开后 500 个关键词；条件最多 120 字符、每组最多 24 条、JSON 最多 12 层，版本及字段须有效。

## 统计与样本

统计保留最近 7 个本地日历日的包名及识别结果计数，最多 512 条聚合项，不保存金额、商户、原文或 Activity。投递说明和来源追加不会重复计数。单后台线程合并写盘，约 1 秒延迟，强杀可能损失最近计数；统计不纳入账单备份。

诊断页主动保存的样本位于应用私有 `files/samples/`，`index.txt` 记录文件名、时间、包名、来源、结论和 Activity；重名自动加后缀，保留原文及 Kotlin 夹具导出。样本包含用户主动保存的页面内容，与不含原文的聚合统计不同。

## 核查依据与边界

实现位于 `LocalRules.kt`、`LocalRuleStore.kt`、`ExternalRuleCodec.kt`、`ExternalRuleStore.kt`、`CategorySuggester.kt`、`BillWriter.kt`、`ui/LocalRulesPage.kt`；页面安全判断仍由billkit规则链负责，G阶段PageCaptureEligibility在个人/外部解析前限制自动入口为详情；付款结果可读预览不代表能自动生成草稿。

## 当前备注规则

支持 9 个变量：商户、支付方式、分类、账户、时间、日期、星期、二级分类、商品。模板页输入/变量插入/示例预览后明确保存；预设列表已移除，恢复默认只改草稿，未保存返回先确认。商品只接受可靠明确字段。1.3.0起可在“识别规则→备注填充”开启商品说明优先，或按商家选择填充方式；备注模板变量和点选建议仍保留。手工输入、明确清空和点选后不被后续自动覆盖。商品候选/来源及备注所有权随识别历史与 JSON9 保存，不影响金额、交易身份或学习次数。旧账单/导入备注不随模板批量重写。

识别来源限制不等于账户/分类限制：银行账户、支付方式映射、手动学习和餐段继续保留，不能把它们当银行采集支持。

## 独立交易规则包（引擎 API 1）

从项目 GitHub Release 下载 `MyMoney-rules-X.Y.Z.mymoney-rules.zip`。设置 → 识别规则 → **导入规则包**，选择下载的文件，等待校验与自检，核对版本和新增/更新/移除清单，再点“确认导入”。不需要解压，不导入 APK。

- 规则可单独发 Release，也可和新 App 放在同一次 Release；这两种来源使用完全相同的包。支持导入的最低 App 版本为 **1.1.0/111**，实际兼容性按包格式、引擎 API 与必要能力检查。
- 首份规则包版本 **1.0.0**，14 条规则保持原行为；不含新的还款适配。包版本与 App 版本互相独立。
- 导入包用于后续识别，立即生效。重新打开 App 或升级兼容 App 会保留该包，不被内置旧规则覆盖。
- 支持查看并逐条启停规则、回退上一包或恢复内置；按稳定规则 ID 保留启停设置。完整快照会移除已不在新包清单内的旧脚本。
- 同版本同内容重复导入不变更；同版本不同内容会被拒绝。降级时预览明确显示降级，用户确认后才执行。
- 文件损坏、不兼容或自检失败会保留原规则。若活动包在冷启动时损坏或不兼容，会提示错误，交易脚本暂不可用；可回退或恢复内置，其他采集通道仍按开关工作。
- 更多选项中的“用已有记录检查”只读取最近20条凭证并显示匹配字段，不补账、不学习、不弹卡。已经在详情页补过的账不会因导入再次处理。
- 交易规则包与下面的“页面与关键词 JSON”分别管理。账本 JSON9 备份不包含交易规则包，迁移手机时另行保留下载的 ZIP 并导入。

规则包只能处理宿主已采集且允许进入的微信/支付宝 DATA/NOTICE 输入。底层 Hook 接口、通知准入或原生页面分类逻辑发生变化时，仍需要更新 App。请从维护者发布的 Release 获取脚本包；SHA256 用于核对文件完整性，不代表发布者签名。

维护者操作与协议见 [规则包维护说明](../billkit/rules/README.md)。

## App内添加个人规则（1.2.0起）

设置 → **识别规则**。首屏直接显示已有规则，按“全部 / 我的 / 微信 / 支付宝”筛选，每条有中文用途、来源和开关。现有内置规则可直接使用，不必先导入任何文件。

1. 点 **添加规则**，填名称、应用、支出/收入/退款及“包含文字”。也可点“从未识别记录开始”自动带入最近的页面或支付凭证。
2. 默认用于交易详情的页面识别，需开启页面识别，无需Root；在“更多条件”可改为支付凭证或交易通知，仍需对应采集通道开启。聊天通知不会因此被放行。
3. 用一条记录，或手工填写示例标题、说明、商户，点 **预览结果**。金额需明确，如¥12.34；示例只测试，不生成账单。
4. 预览正确后点 **保存规则**。修改条件或示例后须重新预览。返回时有未保存修改会询问是否放弃。
5. 在“我的”筛选中点规则可以编辑或删除；开关立即生效。个人规则优先于官方包，多条符合时最近保存的个人规则优先。

个人规则只支持成功且金额明确的支出、收入、退款；失败/取消/进行中、外币和多个不同金额不生成草稿。金额冲突不能通过切换金额位置绕过。转账、提现、充值等特殊资金流继续使用内置规则，不允许用个人规则猜测双端账户或交易方向。页面规则复用列表/输入页负向检查，并拒绝聊天Activity和截断页面。

**更多选项**提供导出我的规则（可备份或自行分享）、用已有记录检查、恢复官方包，以及原有页面/关键词JSON功能。个人规则是独立的 `MyMoney-personal-rules.json` 文件，通过同一个“导入规则包”按钮预览导入；同ID更新、其他个人规则保留。官方ZIP更新、回退、恢复内置均保留个人规则和开关。个人规则不会写进官方ZIP或账本JSON9，换机请另行导出并导入。

支持的第一版仅处理当前微信/支付宝页面与标准支付凭证/交易通知；未采到的数据不能靠规则凭空恢复。保存、导入与试跑不自动补记已有交易。

## 支付宝支出通知更新（1.2.1起）

App1.2.1/113随应用修补了本次支付宝小米渠道。规则包1.1.0也附带相同通知模板，之后支持notification-template-v1的App可直接导入同能力新版规则包，无需反复升级App。旧App需先升级一次，不兼容文件会拒绝导入。

仍从“设置→识别规则→导入规则包”操作；付款通知开关同时控制声明式模板，不需要个人新增一条支付宝规则。奖励尾句里的红包/积分金额不算付款金额；通知未提供商户、付款方式或订单时不猜。规则更新只处理之后的交易，不补记旧通知。个人规则照常保留。

## 商品说明自动备注（1.3.0/114起）

入口：设置→识别规则→备注填充。默认开启“商品说明优先”：新识别带有可靠商品说明时，用本次原文填写备注，列表优先显示备注；交易商家独立保存。关闭后恢复默认模板和建议行为。没有商品时默认仍沿用备注模板，不从以前的备注猜本次商品。

“添加商家备注规则”按应用、交易类型、完整商家名称精确匹配，提供：使用本次商品说明（缺商品留空）、固定文字（明确填写）、不自动填充（留空可手写）。淘宝闪购、美团等平台建议用动态商品说明，避免不同店串用固定内容。规则可编辑/删除，未保存取消不影响设置。

确认卡备注区也有“填充方式”，自动带入当前应用、商家和类型；保存后用于未来识别，当前仍是自动备注时同时更新。当前手动备注/清空/已接受建议会保留，既有账单不批量修改。固定文字不会自动抄入上一次商品。

通知/凭证没有商品信息时无法还原商品，仍需页面提供实际字段；截断、歧义或不可靠字段不猜。新采集同笔补充商品只更新未编辑且未保护的自动备注，不放松交易身份或去重规则。

备注策略随账本JSON9的可选ledger.noteFillPolicy字段备份，Room9不变；旧备份缺项保留当前策略，新版备份可恢复三种模式和默认开关。旧App不认识新增配置，完整恢复需1.3.0或更新版本。个人识别规则仍按原方式单独导出，官方规则包更新/回退不覆盖备注策略。

## 独立规则包1.3.0：微信精简付款与个人场景整合
