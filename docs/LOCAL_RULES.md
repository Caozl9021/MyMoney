# 本地规则与学习

按 **0.6.8 / 27**（2026-10-23）源码核对。设置 → 本地规则管理可配置规则文件、餐段、学习及近7天统计。已实现原计划 B0–B5、B7（B3并入B7）；B6/B8和 [plan1.0](PLAN_1.0.md) 新增条目不应据此视为完成。总体进度及待验收状态见 [PROGRESS.md](PROGRESS.md)。

## 推荐优先级与学习

分类和账户分别评分选择，各自显示来源；仅使用当前分类/账户清单中存在的名称。来源基础权重从高到低为：手动学习600、导入JSON500、随包JSON400、确认学习300、基础规则200、餐段100；匹配细节参与评分。手动确认页仍可覆盖推荐。

- 人工成功保存后，明确修改分类/子类或账户会立即记住；沿用同一推荐连续成功确认3次后才形成确认学习。
- 分类按账单类型与规范化商户识别；账户还关联支付方式，避免同商户不同支付方式串用账户。分类与账户独立累计。
- 取消、忽略、重复、保存失败及自动确认不累计学习。历史账单编辑的明确修改可学习，但不会累计「接受3次」次数；普通手动新增不用于这条确认学习链路。
- 关闭学习会同时暂停新增学习与已有学习推荐。可以单条删除或清空；删除后新确认重新累计，已有手动学习不被弱确认学习覆盖。
- 学习记录与餐段保存在本机，随账本备份；删除分类或账户后，对应无效名称不再推荐。

餐段使用账单发生时间和本机时区，起点包含、终点不包含，支持跨午夜、禁止重叠。默认早餐05:00–10:30、午餐10:30–14:30、晚餐16:30–21:00、夜宵21:00–05:00，空档按现有清单回退三餐或餐饮一级；明确咖啡、零食等子类保持原样。页面可补齐缺少的早餐/午餐/晚餐/夜宵子类，不覆盖已有配置。

## JSON 文件（version 1）

先从页面导出当前JSON作为模板，编辑后导入。导入失败保留当前覆盖文件与正在使用的规则；整份校验通过后才原子替换。恢复随应用规则仅移除导入覆盖，保留学习与餐段。

覆盖文件是增补：同一字段冲突时按优先级评分，未命中的随包规则仍保留；导入空数组不会禁用随包规则。列表、支付输入等反向排除优先，JSON页面规则不能绕过成功状态和金额校验。

根对象为 `version:1`、`rules`（页面）、`categories`（分类）、`accounts`（账户）；完整示例见 [`rules.json`](../app/src/main/assets/rules.json)。

- 页面字段：`packages`包名数组、`kind`现有PageKind、`require`条件数组、可选`anyOf`条件组数组、可选`exclude`条件数组、`strategy`名称。所有require须命中，每个anyOf组至少命中一个，任一exclude命中即拒绝。
- 分类字段：`type`（EXPENSE/INCOME/REFUND/TRANSFER）、`keywords`文字数组、`category`和可选`subCategory`。账户字段以`account`代替分类，默认`matchMethod:true`匹配支付方式；分类默认匹配商户及备注，也可显式设置`matchMethod`。
- 支持`match:"contains"`或省略。关键词为普通文字；页面表达式只支持`|`文字备选，例如`支付成功|交易成功`，不执行任意正则。`regex`与未知字段会被拒绝。
- 文件最多64KiB、总计200条规则、展开后500个关键词；条件最多120字符、每组最多24条、JSON最多12层，版本及字段须有效。

## 统计与样本

统计保留最近7个本地日历日的包名及识别结果计数，最多512条聚合项，不保存金额、商户、原文或Activity。投递说明和来源追加不会重复计数。单后台线程合并写盘，约1秒延迟，强杀可能损失最近计数；统计不纳入账单备份。

诊断页主动保存的样本位于应用私有 `files/samples/`，`index.txt` 记录文件名、时间、包名、来源、结论和Activity；重名自动加后缀，保留原文及Kotlin夹具导出。样本包含用户主动保存的页面内容，与不含原文的聚合统计不同。
