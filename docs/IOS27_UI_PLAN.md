# 历史UI设计草案（项目内部参考）

本文为早期视觉探索留档；“iOS 27”“规范”“三家共识”等表述来自当时设计草案，不作为经验证的系统规范或当前产品承诺。保留以解释旧设计取舍，不作为新实施待办。

当前固定轻透dock为60dp，图标留白/主题/字号/系统入口等已实现；外观没有玻璃强度滑块，不恢复全宽滚动遮罩。后续紧凑确认卡等需求见[plan1.0](PLAN_1.0.md)，实现和验证见[PROGRESS](PROGRESS.md)。本文旧参数、待决策清单、测试数及版本号均为历史。

## 1. 调研结论：iOS 27 的规范到底要求什么

### 1.1 Liquid Glass 在 iOS 27 的地位

- iOS 26 引入的 **Liquid Glass** 不仅没被废弃，iOS 27 里继续**强制推进**：Xcode 27 起取消开发者此前可用的「延期适配」开关，官方要求 App 100% 适配这套半透明圆润设计（[爱思助手报道](https://all.i4.cn/news_detail_55914.html)）。
- iOS 27 的具体改进：**折射更均匀、对比度更高**，App 图标「更清晰、更精致」，并新增**透明度 / 着色滑块**让用户自己调玻璃强度（[IT之家](https://m.ithome.com/html/1001921.htm)）。
- 对第三方 App 的启示：**玻璃是「控件层」的材质，不是「内容层」的皮肤**。Apple 的表述是控件浮在内容之上、玻璃框住内容而不是遮挡内容；把玻璃糊到内容卡片上会破坏它的采样模型（[Liquid Glass API 参考](https://github.com/Prisma-Labs-Dev/apple-skills/blob/main/skills/ios-liquid-glass/SKILL.md)）。

### 1.2 三条设计原则（我们照着做）

| 原则 | 含义 | 落到本 App |
|---|---|---|
| **Hierarchy 层级** | 控件浮于内容之上，玻璃只做「框」 | 导航栏 / Tab 栏 / 底部 Sheet 用玻璃；账单卡片、统计卡用实色内容面 |
| **Harmony 和谐** | 与硬件同心圆角、流体手势 | 卡片圆角与屏幕圆角同心；Sheet 可拖拽；点击有缩放与触感反馈 |
| **Consistency 一致** | 同一身份，跨尺寸自适应 | 一套 Token（颜色/字号/圆角/间距）贯穿 5 个页面 |

### 1.3 需要遵守的硬指标

- **44×44pt 最小触控区**（Android 按 48×48dp 落地更稳）。
- **Dynamic Type**：字号层级化，正文 17、辅助 15/13、说明 12/11；支持系统字体缩放。
- **Reduce Transparency**：降低透明度时玻璃要更「磨砂」；**Increase Contrast** 时加实描边；**Reduce Motion** 时减弱/取消动效。
- **SF Symbols 式图标语义**：线性、圆头、状态靠填充/着色区分，不用彩色插画图标。
- **8pt 网格**：间距取 4 / 8 / 12 / 16 / 20 / 24 / 32。
- **inset grouped 列表**：分组标题 13sp 大写次级色；组内一张圆角卡，行间分隔线**左侧缩进**；行高 ≥ 44。

### 1.4 排版与颜色基线（iOS 语义值 → Compose）

| Token | iOS 值 | 我们用什么 |
|---|---|---|
| Large Title | 34 Bold | 34sp / W700，页首左对齐，滚动后收缩为 17sp 居中 |
| Title2 | 22 Bold | 卡片大标题 / 统计主数字 28–34sp |
| Headline | 17 Semibold | 列表主行、按钮 |
| Body | 17 Regular | 正文 |
| Subhead | 15 | 次要正文 |
| Footnote | 13 | 分组标签、辅助信息 |
| Caption1/2 | 12 / 11 | 时间戳、脚注 |
| Label | #000 / #FFF | `onSurface` |
| Secondary Label | 60% | 副标题 |
| Tertiary Label | 30% | 占位、分隔说明 |
| System BG / Secondary BG | #FFF / #F2F2F7（深色 #000 / #1C1C1E） | 页面底 / 卡片底 |
| Separator | 30% 灰 | 列表分隔线 |
| System Red / Green | #FF3B30 / #34C759 | 支出 / 收入金额 |

数字统一用**等宽数字**（`FontFeature("tnum")`），避免金额跳动。

## 2. Android 上的关键取舍：玻璃怎么落地

这是本方案唯一的「技术风险点」，先说清楚。

| 方案 | 做法 | 兼容 | 依赖 | 评价 |
|---|---|---|---|---|
| **A. 拟态玻璃（推荐）** | 半透明白/黑 + 背景自然透出 + 1dp 上亮下暗渐变描边 + 内高光 + 轻微饱和度叠加 | 全版本（26+） | 0 | 视觉上 90% 像，性能最好，无坑 |
| **B. 真背景模糊** | 引入 [Haze](https://github.com/chrisbanes/haze)（或自研 RenderEffect 抓背景） | 31+ 真模糊，低版本降级 | +1 依赖 | 最像，但要新增依赖、滚动时每帧重采样有掉帧风险 |
| **C. 双轨** | 默认 A；API 31+ 且设备性能允许时叠加真模糊 | 全版本 | 0~1 | 复杂度翻倍，收益有限，**不首推** |

> 说明：Compose 的 `Modifier.blur` 在 API < 31 是 no-op，且只能模糊「自身内容」而不是「身后的内容」。真正的毛玻璃必须抓背景，这正是 Haze 干的事。所以「不引依赖」就意味着走 A。
>
> 另外 **iOS 27 新增了玻璃强度滑块**，我们对应做一个 App 内开关「降低透明度（关闭玻璃）」：开启后玻璃全部退化为不透明次级底色 —— 既符合无障碍要求，也顺手解决了低端机性能问题。

## 3. 设计系统（先建 Token 和组件，再改页面）

### 3.1 新增文件

```
ui/design/
├─ Tokens.kt        // 颜色/字号/圆角/间距/动效时长
├─ Typography.kt    // iOS 12 级字号表 + tnum 数字样式
├─ Components.kt    // GlassSurface / InsetGroup / ListRow / CapsuleButton / Segmented
├─ LargeTitleBar.kt // 大标题 + 滚动收缩 + 玻璃背景
└─ LiquidTabBar.kt  // 悬浮胶囊 Tab 栏
```

`ui/Theme.kt` 从「空壳 MaterialTheme」升级为：语义色 + 排版 + 形状 + 是否开启玻璃的 `CompositionLocal`。

### 3.2 自查清单（每个组件都要满足）

- [ ] 触控区 ≥ 48dp，按压有 scale 0.97 + `HapticFeedback`
- [ ] 深色模式自动适配（不硬编码 `Color.White` / `Color(0xFFEDEFF3)` —— 现在 `ConfirmActivity.kt`、`StatsScreen.kt` 里都是硬编码）
- [ ] 「降低透明度」开关生效
- [ ] 金额用 tnum，长商户名省略号

## 4. 页面级改造

### 4.1 导航壳（`MainActivity.kt`）

现状：`Scaffold` + `TopAppBar`（标题就是「首页/明细/统计/设置」）+ M3 `NavigationBar`。

改为：

```
┌───────────────────────────────┐
│  本月                    ( ○ )│ ← 大标题(34B) + 右上圆形玻璃按钮
│                               │
│   [内容区，可滚动]             │
│                               │
│      ╭───────────────────╮    │ ← 悬浮玻璃胶囊 Tab 栏
│      │ ⌂   ▤   ◔   ⚙    │    │   高 60dp / 圆角 30 / 左右 16dp
│      ╰───────────────────╯    │   选中项 44dp 胶囊 + accent 10% tint
└───────────────────────────────┘
```

- 去掉 `TopAppBar`，改 `LargeTitleBar`：内容上滑时标题从 34sp 收缩到 17sp，玻璃背板淡入。
- Tab 栏悬浮、半透明、内容从它下面穿过（`Scaffold` 的 bottomBar 换成 overlay，content padding 手动给 96dp）。
- 图标换成 **Material Symbols Rounded** 风格（`material-icons-extended` 或手绘 4 个 vector）。
- 页面切换加 150ms 交叉淡入（`AnimatedContent`），不搞花哨转场。

### 4.2 首页（`HomeScreen.kt` + `SummaryCard.kt`）

现状：紫蓝渐变卡 + `OutlinedCard` 列表，每行一张卡（很 Android）。

改为 iOS「大数字 + inset 分组」：

```
│  本月                          │
│  ┌───────────────────────────┐ │
│  │ 支出                       │ │
│  │ ¥ 1,234.56                │ │ ← 34sp W700 tnum
│  │ ─────────────────────     │ │
│  │ 收入 8,000.00   结余 6,7… │ │ ← 15sp 次级色
│  └───────────────────────────┘ │
│  最近记录              全部 >  │
│  ┌───────────────────────────┐ │
│  │ 🛒 瑞幸咖啡         -18.00 │ │
│  │    餐饮·咖啡 10-21 14:03   │ │
│  │ ──────────────────────    │ │ ← 分隔线从 60dp 起
│  │ 🚕 滴滴出行         -32.40 │ │
│  └───────────────────────────┘ │
```

- **移除渐变卡**：渐变紫蓝是最「非 Apple」的元素之一。品牌薄荷绿降级为 accent（唯一的品牌痕迹），统计/图标着色用它。
- 列表合并成**一张** inset 卡（`InsetGroup`），行高 60dp，左侧 40dp 圆角方形分类图标（accent tint 12% 底 + 线性图标），中间商户 + 次级信息，右侧金额（支出 label 色，收入 system green）。
- 空状态：居中图标 + 一句说明 + 一个 capsule 主按钮「去开启识别」。

### 4.3 明细（`BillsScreen.kt`）

- 大标题「明细」+ 右上圆形「筛选」玻璃按钮（P1 功能，纯 UI 阶段先占位或不放）。
- 分组头不再是 `Text`，改成 13sp 次级色 + 右侧当日合计；每天一张 inset 卡。
- **每行右侧「删」按钮删除** → 改成**左滑露出红色「删除」**（`SwipeToDismissBox`），iOS 标配。
- 点行 → 弹出详情 Sheet（P1：可编辑金额/分类/账户）。
- 空状态与首页统一。

### 4.4 统计（`StatsScreen.kt`）

- 大标题「统计」，标题行右侧嵌月份切换 `‹ 2026年10月 ›`（P1 才真做切换，纯 UI 阶段先只显示本月）。
- 顶部一张概览卡（复用首页组件）。
- **分段控件**切换「分类 / 账户」（替代现在上下两张卡）。
- 条形图：8dp 圆角细条、分类色板（iOS system 色 10 色）、金额右对齐 tnum，百分比用 13sp 次级色。
- 底部「本月合计」并进概览卡，不再单开一张卡。

### 4.5 设置（`SettingsScreen.kt` + `LedgerConfigCard.kt`）—— **改动最大**

现状：一个长滚动页里塞了 7 张卡，分类/账户编辑器直接内嵌在页面上，chips 换行铺满。

改为 iOS Settings 的分组 + 子页：

```
│  设置                                  │
│  自动记账                              │ ← 分组标题（13sp 次级色）
│  ┌───────────────────────────────────┐ │
│  │ 启用识别                    ( ●) │ │
│  │ 识别后自动弹确认卡          ( ●) │ │
│  │ 截图 OCR 兜底               ( ○) │ │
│  └───────────────────────────────────┘ │
│  权限                                  │
│  ┌───────────────────────────────────┐ │
│  │ 无障碍服务      运行中          > │ │
│  │ 悬浮窗          已授权          > │ │
│  └───────────────────────────────────┘ │
│  账单                                  │
│  ┌───────────────────────────────────┐ │
│  │ 支持的应用        8 个          > │ │
│  │ 分类与账户        12 类         > │ │
│  │ 备注模板          {商户}…      > │ │
│  └───────────────────────────────────┘ │
│  ... Root / 导出 / 诊断（诊断默认折叠）│
```

- `Switch` 用 iOS 观感（绿色，`SwitchDefaults.colors` 调 accent）。
- 带 `>` 的行进入**子页**：`支持的应用` 变成可勾选列表页；`分类与账户` 变成列表页（一级分类 → 二级分类），编辑器从主页面移走。
- 诊断信息默认折叠（现在直接把 180dp 的等宽文本铺在页面上，iOS 不会这么干）。
- 实现方式：手写一个极简的页面栈（`rememberSaveable` 存 `List<Screen>`），**不引入 navigation-compose**，省一个依赖。

### 4.6 确认卡（`ConfirmActivity.kt`）—— 用户每天看最多次的界面

现状：白色顶部圆角 `Surface` + `OutlinedTextField` 大金额 + 两排 `FilterChip` + 行内文字按钮。

改为 iOS Sheet（`ConfirmActivity` 的 `Translucent` 主题保留，`backgroundDimEnabled` 继续用）：

```
        ╭──────╮                        ← 36×5 抓手（可下拉关闭）
        │      │
╭───────┴──────┴──────────────────────╮
│  [ 支出 | 收入 | 转账 ]              │ ← 分段控件
│                                      │
│              ¥ 18.00                 │ ← 48sp W700 tnum，居中，点按可改
│                                      │
│  分类                                │
│  ┌────┐ ┌────┐ ┌────┐               │ ← 3 列 tinted 图标方格
│  │餐饮│ │交通│ │购物│               │   选中 = accent 填充
│  └────┘ └────┘ └────┘               │
│  咖啡 · 午餐 · 外卖  （二级，横滚）   │
│  账户   [微信] [支付宝] [现金]        │
│  备注   ____________________          │
│                                      │
│  忽略                     [ 记一笔 ]  │ ← 主按钮 capsule，通栏
╰──────────────────────────────────────┘
```

- `导入 iCost` 从并排按钮降级为 sheet 右上角文字按钮（它是低频、且是「另一条落点」）。
- 分类选择从「chip 横滚」改为 **3 列 tinted 方块**（iOS 记账类 App 的通用形态，比横滚 chip 好点）。
- 拖拽下拉关闭用 `Modifier.draggable` + 位移阈值；不做真 detents（Android 没现成组件，成本高收益低）。
- 备注用无边框内联输入（iOS 表单行），不再用 `OutlinedTextField`。

## 5. 不改的东西（重要）

- **识别链路（billkit）一行不动**：`PageClassifier` / `AmountParser` / `BillPipeline` 与 UI 完全解耦。
- **存储与迁移不动**：Room v2、`LedgerConfig`、`PendingStore`、CSV 导出格式全部保持。
- **72 个单测必须保持全绿**（UI 层的改动不在单测覆盖范围内，但要跑一遍确认没有误伤构建）。
- `ConfirmDelivery` 的投递逻辑、BAL 豁免、`OverlayAnchor` 不动。

| 阶段 | 内容 | 验收 |
